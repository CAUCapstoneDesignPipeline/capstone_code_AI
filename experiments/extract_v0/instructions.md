### 추출 시험 v0 (1주차)
---
#### 실험 목적
- LLM이 여러 노트를 함께 보고 노트 사이의 관계를 찾아내는지 평가합니다.
- 찾아낸 관계의 근거가 각 노트 원문에 실제로 있는지 평가합니다.
- 노트마다 다르게 쓴 같은 개념을 LLM이 하나로 묶는지 평가합니다.

#### 준비
- 노트 10~20개를 고릅니다. 주제는 3개 이상이며, 주제가 다르지만 내용이 맞닿는 노트가 들어가야 합니다.
- **추출을 실행하기 전에** 정답 쌍 5~10개와 쌍마다 매개 개념을 적어 둡니다. 매개 개념은 표기 변형도 함께 적습니다 (예: `Bellman 방정식|Bellman equation`).
- LLM에 함께 보여 줄 노트 묶음을 정합니다. 묶음 하나에는 노트를 3~5개 넣고, 모든 정답 쌍이 적어도 한 묶음에 함께 들어가게 합니다. 묶음마다 정답 쌍과 관계없는 노트(같은 주제와 다른 주제를 섞어서)도 넣어, LLM이 없는 연결을 만드는지 확인합니다.
- 묶음 목록은 `groups.csv`에 저장합니다.

#### 절차
| 순서 | 항목 | 설명 |
|--|--|--|
| 1 | 노트 묶음 불러오기 | 준비 단계에서 정한 노트 묶음을 불러옵니다. |
| 2 | 관계 추출 | LLM에 묶음 안의 노트를 모두 함께 주고, 서로 다른 노트 사이의 관계를 추출합니다. 관계마다 주어와 목적어가 나온 노트와, 각 노트의 근거 문장을 함께 받습니다. 같은 묶음을 2번 실행해 결과가 흔들리는지 확인합니다. |
| 3 | 개념 병합 | 묶음 안의 여러 노트에서 같은 개념을 가리키는 표기를 LLM이 하나로 묶어 결과표에 기록합니다. 개념 하나가 노트 3개 이상에 걸칠 수 있습니다. |
| 4 | 실행 기록 | 모델, 프롬프트 버전, 원문 응답, 파싱 성공 여부, 시간, 비용을 기록합니다. |
| 5 | 평가 | 2, 3번 단계의 결과를 평가합니다. 자세한 내용은 아래에서 다룹니다. |

#### 평가 지표
판정 기준은 "노트 원문에 그렇게 쓰여 있는가"입니다. 내용의 사실 여부는 보지 않습니다.
- 노트 연결: 정답 쌍 중 두 노트를 잇는 관계를 하나 이상 찾은 비율(재현율)과, 같은 묶음 안의 정답이 아닌 노트 쌍에서 관계를 만든 비율(오연결률)을 봅니다.
- 관계: 맞음 / 유형 틀림 / 방향 틀림 / 근거 불일치 / 없는 관계 (놓친 관계는 따로 기록합니다)
- 근거 문장 (주어 쪽, 목적어 쪽 각각): 원문과 글자 단위 일치 / 변형 / 없음
- 개념 병합: 맞음 / 잘못 합침 / 못 합침
- 매개 개념 (정답 쌍마다): 찾아서 병합함 / 양쪽에 있지만 못 찾음 / 한쪽에만 있음 / 둘 다 없음
- 반복 안정성: 같은 묶음을 두 번 실행한 결과가 겹치는 비율

#### 평가 방식
- 추출에 쓴 모델과 다른 LLM 3개가 각각 채점하고, 다수결로 최종 판정을 정합니다.
- 다수결이 나오지 않으면(세 판정이 모두 다르면) 채점자가 직접 판단합니다.
- 근거 문장의 글자 단위 일치 여부는 LLM이 아니라 코드로 판정합니다.
- 채점자가 관계 50개를 따로 채점해, LLM 다수결과 얼마나 일치하는지 함께 보고합니다.
- 놓친 관계는 채점자가 표본 묶음에서만 기록합니다.
- 각 지표는 비율로 보고합니다 (예: 관계 정밀도 = 맞음 / 전체 관계).

#### 판단 기준 (제안, 첫 회의에서 확정합니다)
- 관계 정밀도가 70% 이상이면 2주차 파이프라인에 연결하고, 50% 미만이면 추출 방식을 재검토합니다.
- 정답 쌍 재현율이 50% 이상이면 지금 설계를 유지하고, 20% 미만이면 설계 재검토 회의를 엽니다.
- 오연결률이 10%를 넘으면 연결 판정 기준을 강화합니다.

#### 결과 저장
결과는 이 폴더의 CSV 파일 3개에 저장됩니다. 여러 값을 한 칸에 넣을 때는 `;`로 구분합니다.

**`groups.csv`**: LLM에 함께 보여 준 노트 묶음입니다. 묶음 1개당 1행입니다.

| 열 | 설명 | 예시 |
|--|--|--|
| group_id | 묶음 번호입니다. 다른 두 파일이 이 번호로 묶음을 가리킵니다. | `g03` |
| docs | 묶음에 넣은 노트 id 목록입니다. LLM에 준 순서대로 적습니다. | `DB-WAL;OS-페이지-캐시-저널링;OS-IPC` |
| gold_pairs | 이 묶음에 함께 들어간 정답 쌍입니다. 쌍은 `+`로 잇습니다. 없으면 비워 둡니다. | `DB-WAL+OS-페이지-캐시-저널링` |

**`results.csv`**: 추출한 관계입니다. 관계 1개당 1행입니다.

| 열 | 설명 | 예시 |
|--|--|--|
| group_id | 관계를 뽑은 묶음입니다. | `g03` |
| run | 같은 묶음을 몇 번째로 실행했는지 나타냅니다 (1 또는 2). | `1` |
| rel_id | 관계 번호입니다. 묶음과 실행 안에서 겹치지 않습니다. | `g03-1-07` |
| subject_doc | 주어가 나온 노트 id입니다. | `DB-WAL` |
| subject | 주어 개념입니다. 노트에 쓰인 표기 그대로 적습니다. | `WAL` |
| relation_type | 관계 유형입니다. `relation_types.json`에 정한 유형 중 하나입니다. | `used_for` |
| object_doc | 목적어가 나온 노트 id입니다. subject_doc과 달라야 합니다. | `OS-페이지-캐시-저널링` |
| object | 목적어 개념입니다. 노트에 쓰인 표기 그대로 적습니다. | `저널링` |
| subject_evidence | subject_doc에서 가져온 근거 문장입니다. 원문 그대로 옮깁니다. | `WAL은 데이터를 쓰기 전에 로그를 먼저 기록한다.` |
| object_evidence | object_doc에서 가져온 근거 문장입니다. 원문 그대로 옮깁니다. | `저널링은 변경 내용을 저널에 먼저 남긴다.` |
| subject_evidence_match | subject_evidence가 원문과 일치하는지 코드로 판정한 결과입니다 (일치 / 변형 / 없음). | `일치` |
| object_evidence_match | object_evidence에 대한 같은 판정입니다. | `변형` |
| certainty | LLM이 매긴 확실성입니다 (0.0~1.0). | `0.8` |
| judge_1 ~ judge_3 | 채점 LLM 3개의 판정입니다 (맞음 / 유형 틀림 / 방향 틀림 / 근거 불일치 / 없는 관계). | `맞음` |
| rel_label | 최종 판정입니다. 다수결 결과이거나, 다수결이 없을 때 채점자가 정한 값입니다. | `맞음` |
| decided_by | 최종 판정을 누가 정했는지 나타냅니다 (`vote` / 채점자 이름). | `vote` |

**`merges.csv`**: 하나로 묶은 개념입니다. 병합한 개념 1개당 1행입니다.

| 열 | 설명 | 예시 |
|--|--|--|
| group_id | 병합이 나온 묶음입니다. | `g03` |
| run | 실행 회차입니다 (1 또는 2). | `1` |
| concept_id | 병합한 개념의 번호입니다. 묶음과 실행 안에서 겹치지 않습니다. | `g03-1-c02` |
| concept | 병합한 개념의 대표 이름입니다. | `로그 선기록` |
| members | 개념에 묶인 노트별 표기입니다. `노트 id: 표기` 형식으로 적습니다. 노트가 3개 이상일 수 있습니다. | `DB-WAL: WAL;OS-페이지-캐시-저널링: 저널링` |
| n_docs | members에 들어간 노트 수입니다. | `2` |
| judge_1 ~ judge_3 | 채점 LLM 3개의 판정입니다 (맞음 / 잘못 합침 / 못 합침). | `맞음` |
| merge_label | 최종 판정입니다. | `맞음` |
| decided_by | 최종 판정을 누가 정했는지 나타냅니다 (`vote` / 채점자 이름). | `vote` |
