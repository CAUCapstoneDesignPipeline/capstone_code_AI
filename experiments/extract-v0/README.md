# 추출 시험 v0 (1주차)

LLM 추출이 쓸 만한 관계를 뽑는지, 개념 병합이 노트 사이를 잇는지, 서로 다른 노트를 잇는 매개 개념이 노트에 실제로 적혀 있는지를 팀원 노트로 잰다. 세부 절차와 채점표 양식은 팀 문서 "CAPSTONE 추출 시험 계획"을 따른다.

**데이터**
- 세 사람의 공부 노트 10~20개. 주제 3개 이상, 주제가 다르지만 내용이 맞닿는 노트 쌍이 들어가게 고른다.
- 외부 LLM 전송에 대한 동의를 받고, 이름·연락처 등은 지운다. 원문은 `ai/data/private/`에만 둔다.
- **추출을 돌리기 전에** "이어진다고 보는 노트 쌍" 5~10개와 매개 개념을 적어 둔다 (정답 연결 목록).

**절차**
1. 채점 기준 확정 (수요일, 이후 변경 금지)
2. 프롬프트 v0: 노트 하나 → 관계 목록 JSON (주어, 관계 유형, 목적어, 근거 문장, 확실성). 관계 유형은 관계 유형 정의서 초안 7개
3. 추출 실행. 모델, 프롬프트 버전, 원문 응답, 파싱 성공 여부, 시간, 비용 기록. 같은 노트를 2번 돌려 결과가 흔들리는지도 본다
4. 개념 병합 표: 같은 개념으로 볼 표기끼리 묶는다
5. 채점: 이건 + 팀원 1명이 따로 채점하고, 다른 판정만 같이 보고 정한다
6. 토요일 공유: 지표 표, 틀린 사례 5~10개, 다음 주 판단

**채점 (판정 기준은 "노트 원문에 그렇게 쓰여 있는가". 사실 여부는 보지 않는다)**
- 관계: 맞음 / 유형 틀림 / 방향 틀림 / 근거 불일치 / 없는 관계 (+ 놓친 관계는 따로 기록)
- 근거 문장: 원문과 글자 단위 일치 / 변형 / 없음
- 개념 병합: 맞음 / 잘못 합침 / 못 합침
- 매개 개념 (정답 쌍마다): 양쪽 명시 / 양쪽 명시지만 미병합 / 한쪽만 / 둘 다 없음

**결과 파일** (이 폴더, CSV): `relations.csv`, `merges.csv`, `pairs.csv`

**핵심 지표와 다음 주 판단 (제안, 수요일 확정)**
- 관계 정밀도: 70% 이상이면 v0로 2주차 파이프라인 연결, 50% 미만이면 추출 방식 재검토
- 없는 관계 비율: 10% 초과면 "노트에 없는 관계 금지" 강화, 간선 검증을 앞당김
- 근거 일치율: 90% 미만이면 근거 위치를 유사도로 찾는 방법 추가
- 잘못 합침 비율: 10% 초과면 자동 병합 기준을 올림
- **매개 개념 연결률** (가장 중요): 50% 이상이면 지금 설계 유지, 20% 미만이면 설계 재검토 회의
