# 개념 연결 파이프라인 설계 (제안)

노트에서 개념을 뽑고, 서로 다른 주제의 노트를 잇는 "새로운 연결"을 찾아 사용자에게 후보로 보여 주는 AI 파이프라인의 설계안입니다. 핵심 원칙은 **결정성**입니다. 같은 입력에는 언제나 같은 결과가 나와야 하며, LLM은 결과를 바꿀 수 없는 좁은 자리에서만, 캐시와 함께 씁니다.

---

## 1. 배경과 근거

추출 시험 v0(1주차)에서 확인한 내용입니다.

| 관찰 | 수치 | 설계에 주는 의미 |
|--|--|--|
| LLM 추출 결과가 실행마다 크게 다르다 | 같은 노트 2회 실행 겹침 30~45% | 추출의 중심을 LLM에서 결정적 방법으로 옮긴다 |
| LLM 근거 인용은 정확하다 | 원문 글자 단위 일치 100% | 근거는 인용이 아니라 원문 위치(offset)로 저장해도 충분하다 |
| 연결 실패의 주원인은 표기 차이다 | `Bellman 방정식` ↔ `Bellman equation`, `WAL` ↔ `Write Ahead Logging` | 표기 통일(별칭 병합)이 핵심 단계다 |
| 빈도 기반 추출만으로는 부족하다 | LLM 개념 대비 빈도 43%, TF-IDF 49%, TF-IDF+제목·굵게 77% | 통계 + 마크다운 구조를 함께 쓴다 |
| 노트 묶음을 LLM에 함께 보여 주는 방식은 확장이 어렵다 | 노트 n개에 쌍 n²개, 묶음 결과는 캐싱 불가 | 연결 후보는 그래프로 만들고 LLM은 상위 후보만 본다 |
| 오류 상당수가 관계 유형 부족에서 왔다 | 유사·대응 관계를 `contrasts_with` 로 잘못 표기 | 관계 유형에 `analogous_to` 를 둔다 |

---

## 2. 원칙

1. **결정성**: 같은 입력(노트, 설정 버전, 모델 버전)이면 같은 결과가 나옵니다. 무작위성이 있는 단계는 시드와 정렬 순서를 고정합니다.
2. **LLM은 마지막, 좁게**: LLM은 후보를 새로 만들지 않고, 결정적으로 만든 상위 후보를 거르고 설명하는 데만 씁니다. 모든 LLM 호출은 입력 해시로 캐싱합니다.
3. **근거는 위치로**: 근거는 LLM 인용이 아니라 노트 원문의 위치(`start_offset`, `end_offset`)로 저장합니다. ERD의 `evidence_span` 설계와 같습니다.
4. **증분 처리**: 노트 하나가 바뀌면 그 노트와 이웃만 다시 계산합니다.
5. **사람이 마지막에 정합니다**: 후보는 사용자가 승인해야 관계가 됩니다 (`candidate` → `review`).

---

## 3. 전체 구조

```
노트 저장
  │
  ▼
① 개념 추출 (결정적) ───────────── 노트 내용 해시로 캐싱
  │  Kiwi 명사구 + TF-IDF + 마크다운 구조 → 개념 언급(mention, 위치 포함)
  ▼
② 별칭 병합 (고정 임베딩 + 임계값) ── 애매한 구간만 LLM, 캐싱
  │  표기가 달라도 같은 개념이면 하나의 개념(concept)으로
  ▼
③ 그래프 구성 ─────────────────── 노트–개념 이분 그래프, 주제 폴더 = 군집
  │
  ▼
④ 연결 후보 생성과 점수 (ABC 모델) ─ 순수 그래프 계산
  │  다른 주제의 두 노트가 공유하는 매개 개념 → 후보, 연결 강도 × 주제 거리
  ▼
⑤ 상위 후보 검증·설명 (LLM, 캐싱) ── 후보를 추가하지 못하고 거르거나 설명만
  │
  ▼
사용자 검토 (candidate → review)
```

---

## 4. 단계별 설계

### ① 개념 추출 (결정적)

**입력**: NFC 정규화한 마크다운 원문. **출력**: 개념 언급 목록 (`Mention`).

1. **전처리**: 코드 블록, 수식, 이미지·링크 주소를 제거합니다. 제거한 구간은 위치 계산에서 원문 기준을 유지하도록 마스킹으로 처리합니다 (지우지 않고 공백으로 덮어 위치가 어긋나지 않게).
2. **후보 생성**
   - **형태소 분석**: Kiwi로 명사(NNG, NNP), 외국어(SL), 한자(SH)를 뽑고, 이어진 명사는 복합 명사구로 묶습니다 (`페이지 캐시`, `buffer pool`).
   - **마크다운 구조**: 제목(`#`), 굵은 글씨(`**`), 표의 첫 열에서 용어를 뽑습니다. 제목의 접두어(`참고1:`, `왜 ~인가`)와 `출처`, `정의` 같은 틀 단어는 규칙으로 정리합니다.
3. **점수**
   - `score(c, n) = tfidf(c, n) + 구조 가중치`
   - 구조 가중치: 제목 1.0, 굵은 글씨 0.5, 표 첫 열 0.3 (같은 용어가 여러 구조에 나오면 가장 큰 값)
   - `tfidf` 는 sublinear TF를 쓰고, IDF는 **고정한 기준 말뭉치**로 계산합니다. 노트가 늘 때마다 IDF를 다시 계산하면 같은 노트의 점수가 바뀌므로, 기준 IDF는 버전을 붙여 주기적으로만 갱신합니다.
4. **선택**: 상위 k개가 아니라 **점수 임계값**으로 자릅니다 (예: `score ≥ τ_c` 또는 구조 가중치 > 0). 상위 k개는 노트 길이에 따라 결과가 흔들립니다.
5. **불용어·필터**: 한 글자 한글, 단일 영문자·숫자, 수식 기호, 팀 공통 불용어 목록(`사용`, `다음`, `문제`, `필요`, `방법` 등)을 제외합니다. 1주차 말뭉치에서 노트 100개 이상에 나온 단어가 출발점입니다.
6. **위치**: 모든 언급은 원문 위치를 가집니다. 저장 기준은 ERD E1에 따라 **UTF-16 코드 단위**이므로, Python 문자 위치에서 변환합니다.

**LLM 보조 (선택)**: 사람이 표시한 개념 대비 재현율이 기준(§7)에 못 미치면, 노트별로 LLM 추출을 추가합니다. 이때도 출력은 `Mention` 형식이고, 키 `hash(노트 내용, 프롬프트 버전, 모델)` 로 캐싱해 같은 노트는 다시 호출하지 않습니다.

### ② 별칭 병합

같은 개념을 가리키는 표기를 하나로 묶습니다. 1주차 실험에서 연결 실패의 주원인이었던 단계입니다.

1. **정확 일치**: 정규화 키(소문자, 공백·기호 제거, NFC)가 같으면 병합합니다.
2. **임베딩 유사도**: 다국어 임베딩 모델 하나를 **버전까지 고정**해 로컬에서 실행합니다 (후보: bge-m3, multilingual-e5). 한국어 ↔ 영어 표기(`벨만 방정식` ↔ `Bellman equation`)를 잇는 것이 목적입니다.
   - 문맥을 반영하기 위해 표기 자체가 아니라 `표기 + 언급 문장` 의 임베딩 평균을 씁니다.
   - **complete-linkage 응집 군집**으로 묶고 거리 임계값을 고정합니다. single-linkage는 사슬처럼 이어져 관계없는 개념까지 합치므로 쓰지 않습니다.
3. **구간 판정**
   - 유사도 ≥ `τ_high` (예: 0.85): 자동 병합 (`concept_merge.method = 'auto'`)
   - `τ_low` ≤ 유사도 < `τ_high` (예: 0.75~0.85): 애매한 구간만 LLM에 표기 쌍과 언급 문장을 보내 판정 (`method = 'llm'`, 캐싱)
   - 그 아래: 병합하지 않음
4. **대표 표기**: 가장 많이 쓰인 표기, 같으면 사전순으로 정합니다. 동점 처리를 고정해야 결과가 같습니다.
5. **사용자 수정 우선**: 사용자가 합치거나 나눈 결과(`method = 'user'`)는 자동 병합보다 항상 우선하며 다시 계산해도 바뀌지 않습니다.

### ③ 그래프 구성

- **노드**: 노트, 개념. **간선**: 노트–개념 (가중치 = 해당 노트에서의 개념 점수).
- **군집 = 사용자의 주제 폴더**: 주제는 사용자가 만든 의미 있는 묶음이고, 계산이 필요 없으며, 노트가 추가돼도 흔들리지 않습니다. 서로 다른 주제를 잇는 연결은 정의상 "새로운" 연결입니다.
- **미분류 노트**: 주제 중심(주제에 속한 노트들의 개념 벡터 평균)과 가장 가까운 주제로 계산용으로만 배정합니다. 사용자의 폴더는 바꾸지 않습니다. 미분류가 많아지면 고정 시드의 Leiden 군집을 보조로 씁니다.
- **허브 개념 처리**: 전체 노트의 일정 비율(예: 20%) 이상에 나오는 개념은 화면에는 남기되 연결 후보 계산에서는 제외합니다.

### ④ 연결 후보 생성과 점수 (ABC 모델)

Swanson의 ABC 모델을 노트에 적용합니다. 노트 a에 A–B가, 노트 b에 B–C가 있으면 A–C는 어느 노트에도 쓰여 있지 않은 연결 후보입니다. B가 매개 개념입니다.

1. **노트 쌍 후보**: 서로 다른 주제에 있고 매개 개념을 하나 이상 공유하는 노트 쌍.
2. **연결 강도** (Adamic-Adar 변형):

   `S(a, b) = Σ_{B ∈ C(a) ∩ C(b)} w_a(B) · w_b(B) / log(1 + df(B))`

   `w_n(B)` 는 노트 n에서 B의 점수, `df(B)` 는 B가 나오는 노트 수입니다. 흔한 개념일수록 기여가 줄어듭니다.
3. **새로움** (주제 거리):

   `N(a, b) = 1 − cos(μ_topic(a), μ_topic(b))`

   `μ_topic` 은 주제에 속한 노트들의 개념 벡터 평균입니다. 가까운 주제끼리의 연결은 덜 놀랍습니다.
4. **최종 점수**: `score(a, b) = S(a, b) · N(a, b)^α` (α는 새로움을 얼마나 중시할지, 예: 1.0).
5. **개념 수준 주장 만들기**: 상위 노트 쌍마다
   - 매개 개념 B를 공유하는 문장·구간에서, 노트 a의 B와 함께 나온 개념 A, 노트 b의 B와 함께 나온 개념 C를 찾습니다 (같은 문장 또는 같은 제목 구간 안의 동시 출현).
   - 근거는 그 문장들의 원문 위치입니다. 이것이 `candidate_step` / `candidate_claim` / `evidence_span` 이 됩니다.
6. **관계 유형 (결정적 1차 판정)**: 근거 문장의 표현 규칙으로 유형을 정합니다. 예: `~의 일종` → `is_a`, `~를 위해` → `used_for`, `~때문에` → `causes`, `~처럼`·`~와 같이` → `analogous_to`, `~와 달리` → `contrasts_with`. 규칙에 걸리지 않으면 `related` 로 두고 ⑤에서 판정합니다.
7. **동점 처리**: 점수는 소수 넷째 자리에서 반올림한 뒤 비교하고, 같으면 노트 id 순으로 정렬합니다. 부동소수 오차로 순서가 바뀌는 일을 막습니다.

### ⑤ 상위 후보 검증·설명 (LLM)

- **대상**: 사용자별 상위 N개 후보 (예: 10~20개)만.
- **입력**: 노트 전체가 아니라 후보 주장과 근거 구간만 보냅니다. 입력이 작아 비용이 낮고 캐싱이 잘 됩니다.
- **출력**: 구조화 출력으로 고정합니다. `verdict ∈ {valid, invalid, unsure}`, 관계 유형(목록 중 하나), 한두 문장 설명.
- **권한**: LLM은 후보를 **거르거나 설명할 뿐** 새 후보나 새 근거를 만들 수 없습니다. `invalid` 는 사용자에게 보이지 않고, `unsure` 는 낮은 순위로 보입니다.
- **캐싱**: 키 `hash(주장, 근거 구간 원문, 프롬프트 버전, 모델)`. 근거 노트가 바뀌지 않으면 다시 호출하지 않습니다.
- 결과는 `verification_result` 에 저장합니다.

## 5. 데이터 계약

모든 추출 방법(통계, 마크다운 구조, LLM)은 같은 형식을 냅니다. 그래서 방법을 바꾸거나 섞어도 뒤 단계는 바뀌지 않고, 방법끼리 같은 기준으로 비교할 수 있습니다. ERD(`concept`, `concept_mention`, `concept_merge`, `evidence_span`, `candidate*`)와 맞춥니다.

```python
from dataclasses import dataclass
from enum import Enum


class Method(Enum):
    TFIDF = "tfidf"
    MARKDOWN = "markdown"
    LLM = "llm"
    USER = "user"


class Rel(Enum):
    IS_A = "is_a"
    PART_OF = "part_of"
    USED_FOR = "used_for"
    CAUSES = "causes"
    REQUIRES = "requires"
    ANALOGOUS_TO = "analogous_to"
    CONTRASTS_WITH = "contrasts_with"
    RELATED = "related"          # 규칙으로 정하지 못한 경우 (⑤에서 판정)


@dataclass(frozen=True)
class Span:
    note_id: str
    note_version: int
    start: int                   # UTF-16 코드 단위 (ERD E1)
    end: int


@dataclass(frozen=True)
class Mention:
    span: Span
    surface: str                 # 원문 표기
    method: Method
    method_version: str          # 예: "kiwi-0.24.0+tfidf-idf2026w40"
    score: float


@dataclass(frozen=True)
class Concept:
    key: str                     # 정규화 키. 같은 개념은 실행마다 같은 key
    label: str                   # 대표 표기
    aliases: frozenset[str]


@dataclass(frozen=True)
class Candidate:
    note_a: str
    note_b: str
    bridge: str                  # 매개 개념 key
    claim: tuple[str, Rel, str]  # (개념 A key, 관계, 개념 C key)
    evidence: tuple[Span, ...]
    strength: float              # S(a, b)
    novelty: float               # N(a, b)
    score: float
```

## 6. 결정성 보장 장치

| 위험 | 대책 |
|--|--|
| 라이브러리·모델 버전 변화 | Kiwi, 임베딩 모델(가중치 체크섬 포함), 불용어 목록, 임계값을 설정 파일 하나에 두고 버전을 붙입니다. 결과마다 설정 버전을 기록합니다. |
| 말뭉치 변화에 따른 점수 변화 | 기준 IDF를 고정하고 버전을 붙여 주기적으로만 갱신합니다. |
| 정렬·동점 | 반복은 항상 정렬된 순서로, 동점은 정해진 키(빈도 → 사전순 → id)로 깹니다. |
| 부동소수 오차 | 비교 전에 반올림합니다 (유사도·점수 소수 넷째 자리). |
| 군집 번호 흔들림 | 군집은 사용자 주제 폴더를 쓰고, 계산 군집은 미분류 보조로만 씁니다. |
| LLM 비결정성 | 모든 LLM 호출을 입력 해시로 캐싱합니다. 같은 입력은 저장된 답을 돌려줍니다. 프롬프트·모델이 바뀌면 키가 바뀌어 다시 호출합니다. |
| 재현 | 실행마다 설정 버전, 모델 버전, 입력 노트 version, 캐시 적중 여부를 기록합니다. |

| 단계 | 지표 | 정답 자료 | 통과 기준 (제안) |
|--|--|--|--|
| ① 개념 추출 | 재현율·정밀도 | 사람이 개념을 표시한 노트 5~10개 | 재현율 70% 이상 (미달 시 LLM 보조 추가) |
| ② 별칭 병합 | 쌍 단위 정밀도·재현율 | 사람이 표시한 별칭 쌍 | 잘못 합침 5% 이하 |
| ④ 연결 후보 | 정답 쌍 Recall@k, MRR | 1주차 정답 쌍 9개 (+ 추가) | Recall@20 50% 이상 |
| ④ 연결 후보 | 숨겼다 다시 찾기 Recall@k | 자동 생성 (아래) | 기준선 대비 개선 |
| ⑤ 검증 | 사람 판정과 일치율 | 상위 후보 표본 | 80% 이상 |
| 전체 | 사용자 승인률 | 앱의 `review` 기록 | 운영 중 추적 |

**숨겼다 다시 찾기**: 정답 표시 없이 할 수 있는 결정적 평가입니다. 한 노트 안에 함께 쓰인 개념 쌍(A, C)을 고르고, 그 문장을 숨긴 뒤 파이프라인이 다른 노트를 거쳐 A–C를 다시 찾는지 봅니다. 시드를 고정해 고른 쌍 목록은 버전으로 관리합니다.

**기준선**: 같은 평가를 (1) 단순 TF-IDF 코사인 유사도, (2) 1주차 LLM 묶음 추출로도 돌려 비교합니다.

---

## 8. 증분 처리

노트가 저장되면 다음만 다시 계산합니다.

1. 노트 내용 해시가 바뀌었을 때만 ① 재추출 (캐시 적중이면 건너뜀)
2. 바뀐 언급의 개념에 대해서만 ② 병합 재판정
3. 그 노트의 개념을 공유하는 노트들(1단계 이웃)과의 후보만 ④ 재계산
4. 근거 구간이 바뀐 후보만 ⑤ 재검증

노트가 지워지거나 근거 문장이 사라지면 `evidence_span.status = 'lost'` 로 표시하고, 근거가 모두 사라진 관계는 `evidence_lost` 로 바꿉니다 (ERD 설계와 같음).

## 9. 일정 (제안)

| 주차 | 만들 것 | 확인할 것 |
|--|--|--|
| 2 | ① 결정적 개념 추출 (위치 포함), 사람 표시 개념 5~10개 노트 | 추출 재현율·정밀도 |
| 3 | ② 임베딩 별칭 병합, ③ 그래프, ④ 후보 점수 | 정답 쌍 Recall@k, 숨겼다 다시 찾기, WAL ↔ 저널링 순위 |
| 4 | ⑤ LLM 검증·설명, 캐시, `candidate`·`review` 연결 | 사람 판정과 일치율, 호출 수·비용 |
| 5 | 증분 처리, 설정 버전 관리, 재현 기록 | 같은 입력 재실행 시 결과 동일 여부 |

## 10. 위험과 대응

| 위험 | 대응 |
|--|--|
| 허브 개념이 모든 노트를 잇는다 | Adamic-Adar 감점 + 노트 비율 상한 |
| 한국어 형태소 분석 잡음 | 마크다운 구조 가중치, 불용어 목록, 사람 표시 자료로 조정 |
| 임베딩 모델이 무겁다 | CPU로 충분한 크기부터 시작하고, 개념 임베딩은 캐싱합니다 (개념 수는 노트 수보다 천천히 늘어남) |
| 평가 자료가 작다 | 숨겼다 다시 찾기로 자동 평가를 보충합니다 |
| 관계 유형 규칙이 적게 걸린다 | `related` 로 두고 ⑤에서 판정, 걸린 표현을 모아 규칙을 늘립니다 |

## 11. 팀 결정이 필요한 항목

1. **관계 유형 최종 목록**: `analogous_to` 추가 여부, `related` 허용 여부 (현재 `relation_types.json` 은 자리표시 초안입니다).
2. **임베딩 모델과 실행 위치**: 로컬 CPU 실행 모델 선택, AI 서버에 포함할지.
3. **임계값 초기값**: `τ_c`, `τ_high`, `τ_low`, 허브 비율, α.
4. **LLM 사용 범위**: ⑤만 쓸지, ①·②의 보조까지 허용할지.
5. **ERD 보완**: 언급별 추출 방법·버전·점수(`concept_mention` 또는 `analysis_job`), 별칭 저장 방식.
