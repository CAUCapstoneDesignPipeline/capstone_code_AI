# 추천 카드의 외부 지식 (요약·출처 URL) — 제안

이슈 [#19](https://github.com/CAUCapstoneDesignPipeline/capstone_code_AI/issues/19). 상태: **AI 에 구현했다 (`POST /internal/v1/external-knowledge`, profile `external-knowledge-llm-1`). 기본 꺼짐** — 운영에서 켜는 것은 아래 "정한 것"의 조건을 BE·배포 담당이 받아들인 뒤다.
계약은 docs 저장소의 `api/ai-openapi.yaml` `/external-knowledge` (`findExternalKnowledge`)이다. 이 문서는 방법 · 출처 검증 기준 · 비용 · 정한 것 · 켜는 법을 적는다.

## 무엇을 만드나

BE 가 추천 카드의 **결론과 근거 문장(A·B)** 을 보내면 AI 가 웹 검색을 **한 번** 하고, 검색 결과에 실제로 나온 페이지 가운데 결론을 뒷받침하는 것을 골라 **한 문장 요약과 출처 URL** 을 돌려준다.
FE 카드의 `externalKnowledge` (`summary`, `sourceUrl`)를 채우는 용도다. 뒷받침하는 출처가 없으면 오류가 아니라 `status: none` 과 빈 목록이다.

## 지금 있는 것 (playground)

`app/services/links/generate.py` 의 새 지식 만들기는 두 문장에서 **결론과 외부 자료를 함께** 만든다. 외부 자료 부분이 이 제안과 같은 일이다.

| 단계 | 하는 일 | 어디 |
| --- | --- | --- |
| 검색 | Anthropic 의 서버 검색 도구 `web_search_20250305`(기본판)를 **한 번**만 쓴다. 동적 필터링판(`web_search_20260209`)은 같은 쌍에서 결과가 같았고 호출당 입력 토큰이 6배였다 | `generate.py`, `anthropic_llm.py` |
| 고르기 | 모델이 검색 결과 가운데 결론을 이어 주는 것을 최대 3개 고르고 `url`·`quote`(그 페이지가 말하는 내용 한 문장)를 쓴다. 제목은 모델이 쓰지 않고 검색 결과에서 가져온다 | `generate.py` `_check` |
| URL 검사 | 검색 결과에 **실제로 나온 URL** 만 남기고(끝의 `/` 등은 정규화) 지어낸 URL 은 버린다. 중복은 하나로 | `generate.py` `_check`, `_url` |
| 출처 판정 | 별도 호출(Sonnet, 웹 검색 없음)이 출처마다 `yes`/`partly`/`no` 를 **제목과 URL 만 보고** 판정한다. 생성 모델이 쓴 요약을 같이 주면 무관한 특허 페이지도 그럴듯하게 요약돼 있어서 검증기가 속았다. `no` 는 뺀다 | `check.py` |
| 개념 형식 | `ExternalSource`: `url` 은 `^https?://\S+$` · 2,048자 이하, `title` 100자 이하, `retrievedAt`, `quote` | `app/schemas/knowledge.py` |

실제 결과: 카드 20장에서 무관한 출처 4개가 빠졌고, 출처가 하나도 남지 않은 카드는 보류된다 ([knowledge-graph.md](knowledge-graph.md) 4.).

## 출처 URL 검증 기준

| 기준 | 상태 |
| --- | --- |
| http·https 만, 2,048자 이하 | **있다** (`ExternalSource` 스키마) |
| 검색 결과에 실제로 나온 URL 만 | **있다** (`generate.py`) |
| 중복 없음, 최대 3개 | **있다** |
| 제목·URL 로 본 결론과의 관계가 `yes`/`partly` | **있다** (`check.py`). 모델 판단이고 사실 확인이 아니다 |
| 사용자 정보(`user:pw@`)·`localhost`·사설 IP·내부 이름 URL 금지 | **계약에만 있고 코드에는 아직 없다** — 구현할 때 넣는다 |
| 요약 300자 이하 | **계약에만 있다** (지금 `quote` 는 600자 이하) |
| 페이지를 실제로 가져와 확인 | **하지 않는다.** 검색 결과에 나온 URL 이라는 것과 제목·URL 판정뿐이다. 페이지 내용이 요약과 같은지는 확인하지 못한다 (페이지를 받아 읽으려면 별도 도구·비용과 승인이 필요하다) |

`summary` 는 모델이 페이지 내용을 옮긴 것이라 **인용이 아니다.** 계약은 그래서 `quote` 라 부르지 않고 `summary` 라 부른다.

## 비용 추정 (실제로 잰 값)

공개 예시 노트의 쌍 6개로 처음부터(저장 결과 없이) 만들어 보았다 (후보 5 · 보류 1, 2026-11-11). 가격은 [공식 가격표](https://platform.claude.com/docs/en/about-claude/pricing) (같은 날 확인): Opus 5.5 입력 $4 · 출력 $20 / MTok, Sonnet 5.5 입력 $2 · 출력 $10 / MTok, **웹 검색 $10 / 1,000회** (결과는 입력 토큰으로도 센다), 캐시 읽기는 Opus 5.5 $0.20 / MTok.

| 항목 | 카드 하나 (중앙값) | 비용 |
| --- | --- | --- |
| 생성 (Opus 5.5) 출력 | 약 1,080 토큰 | $0.022 |
| 생성 입력 (캐시 밖) | 약 190 토큰 (캐시에서 읽은 것 4,000~8,000 토큰은 약 $0.001) | $0.001 |
| 웹 검색 | 1회 | $0.010 |
| **생성 합계** | | **$0.032** (0.028~0.036) |
| 확인 (Sonnet 5.5, 검색 없음) | 입력 약 650 · 출력 약 150 | $0.003 |
| **카드 하나** | | **약 $0.035** |

- **캐시 쓰기는 이 값에 없다.** 시스템 프롬프트(약 4,000 토큰)의 캐시를 처음 만드는 호출은 쓰기 값($5 / MTok)이 더 든다 — 측정 도구가 이 값을 보고하지 않아 **읽은 토큰 수에서 추정한** 값은 호출당 약 $0.02 이고, 그러면 캐시가 식은(5분 동안 호출이 없었던) 첫 카드는 약 $0.055 이다. 5분 안에 이어지는 호출은 따뜻한 값에 가깝다.
- 100장이면 약 $3.5(따뜻) ~ $5.5(식은 것만). 화면에 카드를 최대 5장 보이므로 분석 한 번에 **최대 약 $0.18**.
- 출력 토큰이 비용의 약 2/3 이고 검색 수수료가 약 1/3 이다. 출처 개수(`maxSources`)는 검색 한 번이라 비용을 거의 바꾸지 않는다.
- **줄이는 방법 (잰 것 아님):** 생성을 Sonnet 5.5 로(출력 단가가 절반) · effort 를 낮춰서. 둘 다 품질이 같은지 먼저 재야 한다. 이전 측정에서 Sonnet 은 effort low 에서 검색을 건너뛰고 "새로 말할 것이 없다" 고 답한 적이 있다.
- 한계: 표본 6개, 공개 예시 노트. 검색 결과가 긴 주제나 응답이 긴 카드는 더 든다 (최대 $0.036 까지만 보았다).

## 시간과 용량

한 번에 **15~20초**(검색 왕복 약 9초 + 쓰기)다. 운영 시작값은 `AI_MAX_INFLIGHT=1` 이라 호출 하나가 그동안 처리 자리를 쓴다. 카드마다 호출하면 분석 호출이 429 `AI_BUSY` 를 받을 수 있으므로:
화면에 보일 카드(최대 5장)에만, 분석이 끝난 뒤 따로(비동기로) 부르고, 결과는 BE 가 저장한다 (배포 manifest 는 AI 의 응답 캐시를 꺼 둔다 — 같은 결론을 다시 부르면 다시 과금된다).

## 사용자 데이터

결론과 근거 문장이 모델 제공자로 나가고 검색어에 섞일 수 있다. release manifest 는 "사용자 범위·보존 계약이 승인되기 전에는 응답 캐시 금지" 를 요구한다. 이 operation 을 운영에서 켜기 전에 같은 계약이 필요하다.

## 여럿인가

계약은 **배열(최대 3, 뒷받침이 강한 순)** 로 정했다. FE 명세는 아직 하나(`externalKnowledge` 하나)인데, 배열이면 BE 가 첫 항목을 쓰면 되고 나중에 FE 가 여럿을 보여 주기로 해도 계약이 바뀌지 않는다. 첫 링크가 죽었을 때를 위한 여분도 된다. 비용은 같다.

## 정한 것 (AI 쪽 결정. 바꿀 수 있다)

이슈에서 "팀이 정할 것" 으로 남겼던 것을 AI 담당이 아래처럼 정하고 구현했다. 모두 환경 변수·manifest 로 바꿀 수 있고, 켜기 전에 BE·배포 담당이 3·4 를 받아들여야 한다.

1. **검색**: Anthropic 의 서버 검색 도구 `web_search_20250305`(기본형, 검색 $10/1,000회)를 **호출당 한 번**. 기본형이 최신형보다 입력 토큰이 약 6배 적다. 별도 검색 API 는 쓰지 않는다.
2. **하나인가 여럿인가**: 배열 최대 3, 기본 `maxSources=1`. BE 는 첫 항목을 쓰면 된다 (계약).
3. **비용·한도**: 호출 하나가 검색 1회 + 모델 입력 약 4~7천·출력 약 0.3~1천 토큰 + 출처 판정(작은 모델, 입력 약 650) 이다. **사용자·일 단위 상한은 AI 가 두지 않는다** — 호출 수를 정하는 것은 BE 다 ("시간과 용량" 의 권고: 화면에 보일 카드에만, 분석 뒤 비동기로, 결과는 BE 저장). AI 는 호출마다 `usage` 를 돌려줘 BE 가 비용을 센다.
4. **사용자 데이터**: 결론과 근거 문장이 모델 제공자로 나간다 (검색어에 섞일 수 있다). 응답은 AI 가 저장하지 않는다 (release manifest 는 응답 캐시를 끈다). **보존 계약이 승인되기 전에는 운영에서 켜지 않는다** — 그래서 기본 꺼짐이다.
5. **페이지를 가져와 읽지 않는다.** 요약은 모델이 검색 결과에서 옮긴 한 문장이고 원문 인용이 아니다. 출처가 결론을 정말 뒷받침하는지는 모델 판단이며 사실 확인이 아니다.

## 구현 (`app/services/links/external.py`)

1. 모델이 검색을 **한 번** 하고 `submit_external_knowledge` 로 `{url, summary}` 목록을 낸다 (일반 글로 답하지 않는다).
2. 코드가 거른다: 검색 결과에 없던 URL(지어낸 것), 안전하지 않은 URL(http·https 만, 2,048자 이하, 공백·사용자 정보 없음, localhost·`.internal`·`.local`·사설·링크 로컬 주소 아님), 중복 URL, 비었거나 300자를 넘는 요약(**자르지 않고 버린다**). 제목은 검색 결과의 것을 쓴다 (모델이 쓰지 않는다). `/` 로 끝나는 차이는 같은 URL 로 본다.
3. 남은 출처가 있으면 별도 판정(웹 검색 없음, 검증 LLM, effort low)이 **제목과 URL 만 보고** `yes · partly · no` 를 정한다. 모델이 쓴 요약은 주지 않는다 (무관한 페이지도 그럴듯하게 요약해 판정이 속았다 — [check.py](../app/services/links/check.py)). `no` 와 판정에서 빠진 것은 버린다.
4. `yes` → `partly` 순으로 `maxSources` 개까지. 하나도 없으면 오류가 아니라 `status: none` (200).
5. 응답은 코드가 계약대로 다시 검사한다 (`found` ⇔ 항목 있음, `maxSources` 초과·URL 중복·안전하지 않은 URL·정렬 위반이면 502 `INVALID_MODEL_OUTPUT`). 자동 재시도·모델 fallback 은 없다.

처리 자리는 다른 LLM operation 과 같은 `AI_MAX_INFLIGHT` 하나를 쓰고, 가득 차면 429 `AI_BUSY`, 115초를 넘기면 504 `MODEL_TIMEOUT` 이다. 실측 (공개 문서 같은 결론 3개, 호출 한 번): 4~9초, 검색 1회, 입력 약 3.7~7천 토큰(캐시 읽기 포함)·출력 약 0.2~0.5천. 말이 안 되는 결론(고양이 사료 ↔ 해시 충돌)은 `none` 이었다.

## 켜는 법

| 어디서 | 설정 |
| --- | --- |
| 로컬·서버 환경 변수 | `AI_EXTERNAL_LLM=1` (기본 0). 모델은 `AI_EXTERNAL_LLM_PROVIDER`(anthropic 만)·`_MODEL`·`_EFFORT` (기본 effort medium). 출처 판정은 `AI_VERIFY_LLM_*` 설정을 쓴다. 만들지 못하면 이 operation 만 503 |
| release manifest | 선택: `provider.models.external`·`provider.efforts.external` 와 `flags.external: true`. 켜려면 모델·effort 가 함께 고정되어 있어야 하고, 없으면 host driver 가 `AI_EXTERNAL_LLM=0` 을 명시한다 (옛 manifest 도 그대로 유효). 챗봇(`chat`)과 같은 방식이다 |

배포 도구는 SHA 로 고정되어 있어 이 manifest 선택지는 새 이미지·pin 갱신과 함께 나간다 ([deploy.md](deploy.md)). 꺼진 동안 BE 는 대역(또는 호출 안 함)으로 카드를 채운다.

## 이 문서가 닫지 않는 것

- 운영에서 켜는 일 (보존 계약 승인, 호출 상한 정책, manifest 에 `external` 모델·flag 를 넣은 release) 은 BE·배포 담당 몫이다.
- 출처의 사실 정확성은 검증하지 않는다 (제목·URL 로 본 주제 일치 판정뿐).
