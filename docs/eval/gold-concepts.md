# 정답 개념 표시 기준

개념 추출(①)의 재현율·정밀도를 재는 정답 자료를 만드는 기준이다. 정답 파일은 노트 원문이 들어 있으므로
`data/private/gold/` 에만 두고 저장소에 넣지 않는다.

## 파일 형식 (`data/private/gold/concepts.csv`)

| 열 | 뜻 |
| --- | --- |
| `note_id` | `data/private/notes` 의 파일 이름 (확장자 제외) |
| `concept` | 개념의 표기. 노트에 실제로 쓰인 그대로. 같은 개념의 다른 표기는 `\|` 로 잇는다 (`WAL\|Write Ahead Logging`) |
| `level` | `core`: 노트가 설명하거나 다른 개념과의 관계를 말하는 개념. `mentioned`: 지나가며 나오는 개념 |
| `status` | `draft` (초안, 검토 전) 또는 `reviewed` (사람이 확인함). 평가는 기본으로 `reviewed` 만 쓴다 |
| `split` | `dev` / `test` / 빈칸. 규칙을 고칠 때 들여다본 노트는 dev, 아직 보지 않은 노트는 test. 빈칸이면 hash 로 정한다 |

## 노트 쌍 (`pairs.csv`, `pair-judgments.csv`)

- `pairs.csv` (`note_a,note_b,bridge_concept,status`): 이어진다고 본 노트 쌍. 1주차에 사람이 만든 9쌍은 `reviewed`.
- `pair-judgments.csv` (`query,candidate,label,bridge_concept,reason,status`): 판정 풀(`experiments/gold_pairs/pool.py`)의
  쌍마다 `yes` / `no`. `yes` 는 `pairs.csv` 에도 들어간다. `no` 까지 있어 사용자에게 보이는 상위 3 개의 정밀도를 잴 수 있다.
- **이어진다(yes)**: 두 노트가 모두 실제로 설명하거나 쓰는 기술 개념을 공유하거나, 한쪽 개념이 다른 쪽을 직접 설명한다.
  일반적인 말(데이터, 시스템, 문제)만 겹치거나 한쪽에서 이름만 나오면 no. 목차 페이지(링크 모음)는 늘 no.

## 개념으로 표시하는 것

- 공부하는 사람이 그래프의 노드로 두고 싶을 말: 기술 용어, 이름 있는 알고리즘·프로토콜·자료 구조·기법·정리·식,
  그 분야의 고유한 대상 (예: `WAL`, `페이지 캐시`, `라운드 로빈`, `Bellman 방정식`, `ILF`).
- 노트 본문에 나오는 것만. 코드 블록·URL·이미지 안에만 나오면 표시하지 않는다.
- 가장 구체적인 표기를 쓴다 (`커널 레벨 스레드`). 노트가 일반 개념(`스레드`)도 따로 설명하면 둘 다 표시한다.
- 같은 개념의 한국어·영어·약어 표기는 한 줄에 `|` 로 묶는다. 다른 개념이면 다른 줄이다
  (`트랜잭션` 과 `트랜잭션 격리 수준` 은 다른 줄).

## 표시하지 않는 것

- 일반적인 말: 방법, 문제, 결과, 예시, 정리, 장점, 단점, 과정, 구조 …
- 제목 틀: 핵심 아이디어, 개요, Step 1, Level 3 …
- 예시 속 값: 파일 이름, 비밀번호, 숫자, 변수 이름 (`bandit0`, `x1`)
- 사람·책·강의 이름 (개념 이름의 일부일 때는 표기 그대로: `Bellman 방정식`)

## 채점 (`uv run ai concepts eval`)

- 표기는 대소문자·공백·하이픈을 무시하고 정확히 같아야 맞다 (부분 일치는 틀림).
- **재현율** = 추출 결과에 (어느 표기로든) 나온 `core` 개념 수 ÷ `core` 개념 수. `mentioned` 까지 넣은 값도 같이 본다.
- **정밀도** = 정답의 어느 개념(`core`·`mentioned`)과 맞는 추출 개념 수 ÷ 추출 개념 수.
- 추출 결과는 `/extract` 와 같은 profile 선택 규칙을 거친 개념이다. 신뢰도 문턱값마다 재현율·정밀도를 함께 낸다.
- 통과 기준 (설계 7장): 재현율 70% 이상.
