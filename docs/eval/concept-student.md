# 개념 추출 두 단계: 빠른 학생 `extract-student-1` · LLM `extract-llm-1` — 평가

노트를 저장하자마자 개념을 보여 주려면 LLM 호출(몇 초)을 기다리지 않아야 한다. 그래서 개념 추출을 두 단계로 나눈다 ([흐름](../be-integration.md)).
`extract-student-1` 이 약 0.1초 안에 첫 결과를 주고, 켜 둔 경우 `extract-llm-1` 이 몇 초 뒤 더 정확한 결과로 바꿔 넣는다. 이 문서는 두 profile 의 측정과 한계다.

## 방법

- **후보** (`app/services/concepts/ngrams.py`): 코드·수식·주소를 가린 뒤 형태소 토큰의 연속 구간(최대 6토큰·60자)을 모두 후보로 낸다. 정답 core 개념의 96~98% 가 후보에 든다 (기존 추출기: 과목 노트 85%, 영어 논문 노트 40%).
  기존 추출기는 영어 문장에서 명사구를 만들지 못했고 (모든 영어 낱말을 명사로 읽는다) 낱말 사이 조각을 놓쳤다. 이 후보 생성이 새 분야에서 재현율이 무너지는 문제를 풀었다.
- **학생** (`app/services/concepts/student.py`, `student-1.json`): 후보마다 62개 특징(모양·글자 종류·위치·마크다운 구조·정의와 별칭 같은 문맥 단서)으로 부스팅 트리 150그루가 확률을 낸다. 확률 ≥ 0.45 인 후보 가운데
  모든 언급이 더 긴 채택 후보 안에 든 짧은 후보는 뺀다. numpy 로 트리를 한꺼번에 계산한다 (sklearn 이 필요 없고, 내보낸 트리는 sklearn 확률과 1e-15 안에서 같다).
- **교사**: LLM 이 노트를 읽고 개념 목록을 낸 것(`llm-only-concepts-1`, Opus 5.5, effort medium). 학생은 이 목록을 흉내 내도록 학습한다.
- **LLM profile** (`app/services/concepts/llm_concepts.py`): 같은 LLM 호출로 개념(표기·별칭)을 받고, 코드가 원문에 없는 것을 버리고(단어 경계를 지킨다) 나온 자리를 모두 찾아 UTF-16 위치의 언급으로 돌려준다.
- 관계·근거는 두 profile 모두 기존 규칙(`rules+structure`)이 만든다.

## 학습 자료와 개인 정보

- 정답 없는 과목 노트 100개 + 공개 글 98개 (위키백과, CC BY-SA, 물리·생물·화학·수학/통계·경제·의학·공학·심리·역사/사회·컴퓨터·지구/환경·신경과학 12 분야, 한국어·영어 각 절반). 공개 글은 학습에만 쓰고 저장소에 넣지 않았다.
- 정답이 있는 노트 41개와 다른 분야 논문 리뷰 18개는 **학습에 쓰지 않았다**. 아래 수치는 이 모델의 수치다.
- 모델 파일에는 숫자(트리의 분기점·잎 값)만 있고 노트 속 낱말이 없다. 말뭉치 통계(문서 빈도)나 교사 라벨 사전은 일부러 쓰지 않았다 (분야·사용자와 무관하게 같은 모델이 돌고, 개인 노트의 낱말이 배포물에 들어가지 않게).
  쓰면 정밀도가 6~14%p 오르지만 (과목 노트 dev, 실험마다 다르다) 노트에서 센 사전이 배포 파일이 된다.

## 결과 (정답은 AI 초안 · 사람 검토 전, 재현율은 core)

| 노트 | profile | 재현율 | 정밀도 | 개념 수 |
| --- | --- | --- | --- | --- |
| 과목 dev 23 | `extract-student-1` | 78% | 76% | |
| 과목 test 18 | `extract-student-1` | 83% | 65% | |
| 논문 리뷰 18 (다른 분야) | `extract-student-1` | 56% | 68% | |
| 과목 dev 23 | `extract-llm-1` | 96.5% | 90.6% | 807 |
| 과목 test 18 | `extract-llm-1` | 96.1% | 83.2% | 819 |
| 논문 리뷰 18 | `extract-llm-1` | 97.8% | 85.0% | 260 |
| 참고: 과목 dev / test / 논문 | `extract-hybrid-3` (LLM 거르기) | 83 · 84 · 40% | 81 · 73 · 72% | |

- 학생의 임계값(0.45)은 dev 정답 노트의 F1 이 가장 높은 값이다 (0.45~0.50 이 같은 수준, test·논문 리뷰도 그 근처가 가장 좋았다). `student-1.json` 의 `threshold` 만 바꾸면 재현율과 정밀도의 균형을 옮길 수 있다:
  0.25 에서 89/60 · 91/53 · 69/47 (재현율/정밀도), 0.60 에서 67/84 · 73/75 · 45/80.
- **지연** (이 컴퓨터, 후보·특징·모델·위치까지): 학생 노트당 중앙값 27ms, p90 89ms, 최대 458ms. LLM 호출은 약 4.3초 (노트 2.2천 자 3개로 잰 값; 긴 노트는 더 걸리지만 재 보지 않았다).
- 학생은 과목 노트에서 LLM 거르기(`extract-hybrid-3`)와 비슷한 재현율을 호출 없이 내고, 다른 분야에서는 그보다 낫다 (재현율 56% 대 40%). 정밀도는 LLM profile 에 못 미친다.

## 분야 일반화 (학생)

분야 하나를 통째로 빼고 학습해 그 분야의 글에서 교사 개념을 얼마나 찾는지 쟀다 (위키 12 분야, 교사 개념 재현율 / 정밀도):

| 학습 자료 | 재현율 | 정밀도 |
| --- | --- | --- |
| 과목 노트만 | 25.8% | 51.1% |
| 과목 노트 + 나머지 위키 분야 | 42.0% | 56.5% |

학습에 쓰는 위키 분야를 0·3·6·11개로 늘리면 뺀 분야의 재현율이 14% → 29% → 37% → 41% 로 오른다 (같은 실험의 말뭉치 통계를 쓰는 변형). 분야를 더할수록 이득이 줄어든다.
모르는 분야의 노트에서 LLM 수준에 닿으려면 그 분야의 노트로 더 학습하거나 LLM profile 을 쓴다. 학생이 낯선 노트를 알아보고 LLM 에 넘기는 라우팅도 시험했지만 노트 단위 신호로는 가려내지 못했다
(학생과 LLM 의 차이가 노트마다 비슷하게 퍼져 있다: 전체의 50% 를 LLM 에 넘겨도 F1 이 0.77 → 0.84, LLM 만 쓰면 0.91). 그래서 라우팅 대신 "학생 결과를 먼저 쓰고 LLM 결과로 바꿔 넣기" 로 지연을 가렸다.

## 읽을 때 주의

- **정답이 AI 가 쓴 초안이다.** 정답과 교사와 LLM profile 이 같은 계열의 모델이고 프롬프트가 정답 표시 기준을 그대로 옮긴 것이라, LLM profile 의 높은 점수에는 그 일치가 섞여 있다 (독립 검증이 아니다). 사람이 표시한 정답 몇십 개로 다시 재야 한다.
- 노트가 적다 (dev 23, test 18, 논문 18 — 짧은 노트가 많다). 새 분야 수치는 구간이 넓다.
- 학생의 정밀도는 낮다 (60~76%). 첫 결과로 보이는 동안 잡음이 섞이고, LLM 결과가 오면 사라진다. LLM 을 켜지 않으면 학생 결과가 최종이다.
- 교사 라벨을 만드는 데 LLM 호출이 들었다 (과목 노트 100 + 공개 글 98, 한 번). 학습 자료의 개인 노트 내용은 LLM 제공자로 나갔다.

## 다시 학습·재현

```bash
uv run --env-file .env python experiments/llm_only/baseline.py            # LLM profile 과 기존 방법의 점수 (정답 노트, 캐시 사용)
uv run --env-file .env python experiments/distill/teacher.py              # 교사 라벨 (정답 없는 과목 노트; --web 은 공개 글)
uv run python experiments/distill/fetch_web.py                             # 공개 글 수집 (data/private/notes-web)
uv run --env-file .env python experiments/distill/train_student.py --write --threshold 0.45   # 학습 → app/services/concepts/student-1.json
uv run --env-file .env python experiments/distill/eval_profiles.py        # 출고 profile 두 개를 정답 노트에서 측정
```
특징을 바꾸면 `FEATURES` 가 달라져 옛 모델 파일은 읽히지 않는다 — 다시 학습한다.
